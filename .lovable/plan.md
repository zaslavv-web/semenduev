## Уведомление о скачивании чек-листа

Сейчас кнопка «Скачать чек-лист» просто отдаёт PDF — в почту ничего не приходит, источник `checklist` пропал из статистики заявок. Возвращаем уведомление, но без формы: фиксируем сам факт скачивания.

### Что меняем

**1. `src/components/site/Checklist.tsx`**
- На клик по кнопке скачивания дополнительно отправляем `fetch(FORM_ENDPOINT, { keepalive: true })` с телом:
  ```json
  { "source": "checklist", "name": "Скачивание чек-листа", "phone": "—", "message": "Пользователь скачал PDF-чек-лист с сайта" }
  ```
- `keepalive: true` — чтобы запрос ушёл, даже если браузер сразу начинает скачивание/уход со страницы.
- Ошибку игнорируем (не мешаем скачиванию): `.catch(() => {})`.
- Поведение ссылки `download` сохраняем — `e.preventDefault()` не вызываем.

**2. `public/send.php`**
- В словаре `$sourceLabel` метка `'checklist'` остаётся прежней — «Форма "Чек-лист"». Менять её не нужно, валидация `name + phone` проходит за счёт значений-заглушек выше.
- Файл `send.php` не переписываем — контракт совместим.

### Что НЕ трогаем

- Контракт API (`POST /send.php`, JSON, honeypot `website`) — без изменений.
- `Contact.tsx`, маршруты `/contact` и `/thank-you` — без изменений.
- PDF продолжает скачиваться напрямую, без редиректа на «спасибо».

### Технические заметки

- `fetch` запускается синхронно в обработчике `onClick`, ссылка с `download` отрабатывает браузером параллельно — конфликта нет.
- Если в будущем захотите различать «честные» заявки и просто скачивания, в админке/почте сортируйте по теме письма: «Заявка с сайта: Форма "Чек-лист"» = скачивание, остальные источники = реальные формы.

### Файлы

- Изменить: `src/components/site/Checklist.tsx`
- Не менять: `public/send.php`, `src/lib/config.ts`, прочее.
